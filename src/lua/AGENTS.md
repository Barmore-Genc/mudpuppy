Embedded Luau scripting: the configurable keymap and event hooks. A sandboxed interpreter (no io/os/network/subprocess) where all default bindings live in Lua; user config loads on top, last-binding-wins. Bindings are keyed on key *sequences* (multi-key chords, a `<leader>`, and ambient count prefixes); a `:command` palette runs named commands. Scripts read the diff/files/annotations/screen and drive the app through scoped action verbs.

- `mod.rs`: `LuaEngine` (sandbox setup, `core.luau` + user-config load/hot-reload), the sequence-dispatch state machine (pending count + partial sequence on `App`, prefix-wait/exact/miss resolution), `run_command`, leader/command registries, `EventKind`, and `config_path` (hand-rolled XDG resolver).
- `api.rs`: builds the `mudpuppy` table — persistent `map`/`unmap`/`on`/`command`/`leader` registration fns, and the per-dispatch scoped action/reader fns that borrow `&mut App` via a `RefCell` (including `open_palette`, `move_selection`, and the writable `state()` proxy).
- `keys.rs`: `KeyChord` (parse/`from_event`/round-trip), `parse_sequence` (+ `<leader>` expansion), the `KeySeq` alias, the count-digit rule, `Key`, and the `Mode` enum (`Global`/`Tree`/`Diff`/`Help`).
- `views.rs`: read-only Lua tables built on demand from the live `App` — `files`/`current_file`/`annotations`/`screen`, the `state()` proxy's `state_field`/`set_state_field` (the only writable field is `count`), plus shared annotation/turn builders.
- `core.luau`: the embedded default keymap (Space leader, count-aware motions, `:command` palette commands), expressed against the primitive verbs; `include_str!` in release, read from disk in debug so it hot-reloads in dev.
