The ratatui diff viewer, split into the event-loop shell, the state, and the
drawing.

- `mod.rs`: module root — `launch` (also turns mouse capture on/off), the `run_loop` event loop (terminal input, mouse events, store reload, config hot-reload, the one-shot launch-time update check run off-thread via `spawn_blocking` and gated by `MUDPUPPY_NO_UPDATE_CHECK`, the synchronous launch-time stale-skill check that fires `skill_update_check`, modal-prompt key capture, plus the background syntax-highlight worker: drains `take_highlight_request`, runs `highlight::run_request` on `spawn_blocking` with a shared `cancel` generation, and applies results via `apply_highlights`), the notify watchers, and the `Snapshot`/`fire_changes` event-hook diffing.
- `app.rs`: viewer state — `App` and its verbs (count-aware scroll/cursor move/`move_selection`/hunk-hop, visual selection, select, focus, release turn, reload), on-reload anchor relocation (`relocate_annotations`/`capture_signature`/`set_anchor_windows`, `orphaned_anchors`), file filtering (`all_files` canonical list + `reproject`/`set_hidden_files`/`toggle_file_filters`, hiding files the Lua `filter_files` predicates reject while keeping them restorable), the `Sidebar` tab (Files/Annotations) and its `sidebar_*` nav/jump verbs + `annotation_list`, the pending count/sequence fields, the `:command` palette state + `handle_palette_key`, the `Hits` hit-test struct + `handle_mouse_event` (wheel/click/drag/double-click), the `rebuild_view` (= `ensure_structure` + `interleave_annotations` + `clamp_cursor`)/`sync_comment_width`/`focus_composer_row`/`close_composer` view-rebuild verbs, plus `Focus`, the `Row` enum (incl. inline `Comment`/`Composer` rows), and the lazily-built per-file `FileView`. Highlighting is split out and cached: `FileView::structure` builds the annotation-free row layout with un-coloured lines + `HlSegment`s; `base_view`/`view_key`(`BuildKey`)/`highlight_gen`/`pending_highlight` cache that structure keyed on `(selected, plan)` so reload/resize/composer only re-interleave, and the actual colouring runs off-thread (see `mod.rs`), filling `base_view` via `apply_highlights`.
- `interleave.rs`: the `interleave_annotations` pass run after the structure cache is ensured — clones `base_view`'s rows, groups line-scoped annotations into threads, wraps each comment body to single-line `Row::Comment` rows under its diff line, splices the open composer's `Row::Composer` placeholder at its target, and recomputes `hunk_starts`.
- `annotate.rs`: the user's annotation mutations (`impl App`) — cursor/selection → anchor, add/region/file/reply/edit/delete/status writes through `store::update`, `reset_annotations` (clear the whole store), and the delete-confirm key handler.
- `composer/`: the comment composer (`Composer`, `ComposerTarget`, `Mode`), its `handle_composer_key` key handler, the composer-opening verbs, and the vim-like modal editing engine; see `composer/AGENTS.md`.
- `debug.rs`: `mudpuppy debug colors` — a scrollable swatch page of every colour the viewer uses, drawn on the themed background to judge contrast in a real terminal.
- `markdown.rs`: lightweight Markdown styling (`render`) for the prompt's `details` body — headings, lists, blockquotes, fenced code, inline `code`/bold/italic/links — returning pre-wrapped styled lines; used for the self-update changelog.
- `prompt.rs`: the modal question overlay (`Prompt`, with an optional scrollable `details` body) opened from Lua via `mudpuppy.prompt`; `open_prompt` + `handle_prompt_key` (option nav via ←/→, body scroll via ↑/↓/PageUp-Down when details exist, dismiss; returns the chosen option index the engine runs). Labels live here; option callbacks live in the engine.
- `render.rs`: per-frame drawing — one function per pane (the sidebar's file tree / all-annotations tab, diff, status, help, banner) plus the picker, `:command` palette, and modal-prompt overlays, the status-bar pending count/sequence hint, row → styled-line (incl. inline `comment_line` rows), the inline composer popover (`render_compose_box`/`compose_lines`, with the whole-file `render_composer` modal), the small style/format helpers, and per-frame population of `App::hits` (pane rects + clickable label spans) for the mouse handler; defines `MARK`.
- `tests/`: Layer-1 `insta` snapshot + buffer-style tests driving the real keymap through `App::handle_key`; `mod.rs` holds the shared fixtures/helpers, with tests grouped by topic into `rendering`, `keymap`, `annotations`, `turns`, `expansion`, `authoring`, `mouse`, `relocation`.
- `tests/snapshots/`: generated `insta` `.snap` baselines for the tests here.
